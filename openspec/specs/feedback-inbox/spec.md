# feedback-inbox Specification

## Purpose
모든 화면에서 앱 오류 · 집 민원 · 안전 신고 · 제안을 받고, 운영 콘솔에서 끝까지 추적해 개선 방향을 정한다. (REQ_025 ~ 029, POL_REPORT)

## Requirements

### Requirement: 의견 · 신고 보내기

모든 화면의 [💬 의견 · 신고]는 종류 6개 · 글(또는 말) · 화면 사진(선택) · 최근 3분 기록 · 기기 · 판 정보를 함께 보내야 한다(SHALL). 보내기 전에 함께 가는 것을 보여 줘야 한다(SHALL).

#### Scenario: 오류 직후
- **WHEN** 3분 안에 오류가 난 화면에서 신고를 연다
- **THEN** 종류가 🐞 앱 오류로 미리 골라져 있다

### Requirement: 개인정보 화면 보호

내 집 · 본인인증 · 신청 · 운영 콘솔 화면에서는 화면 사진을 찍지 않아야 하고(SHALL), 3분 기록에는 입력값을 남기지 않아야 한다(SHALL).

#### Scenario: 내 집에서 신고
- **WHEN** 내 집 화면에서 신고를 연다
- **THEN** "이 화면은 개인정보가 있어 사진을 찍지 않아요"가 보인다

### Requirement: 안전 신고

🛡 안전을 고르면 "지금 위험하면 112에 먼저 전화하세요"와 [112 걸기]가 보여야 하고(SHALL), 접수 즉시 대표에게 긴급 알림이 가야 한다(SHALL).

#### Scenario: 안전
- **WHEN** 🛡 안전으로 보낸다
- **THEN** 대표에게 긴급 알림이 간다

### Requirement: 신고함 처리

운영 콘솔 신고함은 상태(접수 → 확인 → 처리 중 → 완료 / 보류 · 중복) · 심각도 · 우선순위를 바꿀 수 있어야 하고(SHALL), 상태가 바뀔 때마다 시각 · 처리자를 남겨야 하며(SHALL), 완료에는 원인 / 고친 것 / 확인 방법이 모두 있어야 한다(SHALL).

#### Scenario: 세 줄 없이 완료
- **WHEN** 처리 기록 없이 완료로 바꾼다
- **THEN** `REPORT_422`

### Requirement: 남용 막기

같은 기기 · 계정은 1시간에 10건까지, 사진은 700KB까지만 받아야 한다(SHALL).

#### Scenario: 11번째
- **WHEN** 1시간 안에 11번째 신고를 보낸다
- **THEN** `REPORT_429` "잠시 뒤 다시 보내 주세요"
